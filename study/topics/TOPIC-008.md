# TOPIC-008 — Projeto final: fluxo colaborativo com rebase

## O que você vai aprender

Você vai conduzir, de ponta a ponta, um cenário realista de time: criar feature branches, manter-se atualizado com rebase, abrir e revisar pull requests, e resolver um conflito complexo que surge no caminho — sem entrar em pânico.

## Por que isso importa para você

Este projeto reúne exatamente os dois resultados que você quer levar para o novo time: resolver um conflito de merge complexo com confiança, e revisar/abrir pull requests em um repositório colaborativo com fluxo de rebase e branches de feature. É a prova de que a trilha atingiu o objetivo que você declarou no intake.

## O que você já precisa saber

- **Aula 05 — Conflitos de merge:** você precisa já conseguir resolver um conflito multi-arquivo com método, porque o projeto inclui um conflito real a resolver.
- **Aula 07 — Revisar pull requests:** você precisa já conseguir revisar e responder a um pull request, porque o projeto inclui esse ciclo completo.

## Seu plano para esta etapa

- [ ] Recuperar o que já sabe sobre conflitos e revisão de PR (10 min)
- [ ] Planejar o cenário de time simulado (15 min)
- [ ] Criar a feature branch e mantê-la atualizada com rebase (20 min)
- [ ] Abrir e revisar o pull request do cenário (20 min)
- [ ] Resolver o conflito complexo proposto no cenário (15 min)
- [ ] Documentar as decisões tomadas ao longo do projeto (10 min)

## Aula

Esta aula será preparada automaticamente quando você concluir os pré-requisitos desta etapa (Aula 05 e Aula 07). Você não precisa pedir a geração manualmente.

## Prática

Este projeto integrador substitui a prática isolada: ele é, ele mesmo, a prática guiada e independente da trilha inteira, em um repositório de simulação.

## O que você vai produzir

Um repositório de simulação onde você executou o ciclo completo (feature branches, rebase, pull requests, revisão, resolução de um conflito complexo), com um documento curto explicando cada decisão tomada.

## Como mostrar o que aprendeu

A evidência esperada é o link do repositório ou dos pull requests do projeto, acompanhado do seu documento de decisões.

## Para concluir esta etapa

- [ ] Executar o ciclo completo de feature branch, rebase e pull request.
- [ ] Resolver um conflito complexo com método, sem pânico.
- [ ] Revisar e responder a um pull request dentro do próprio projeto.
- [ ] Documentar as decisões tomadas com justificativa técnica.
- [ ] Alcançar a pontuação mínima da avaliação sem um equívoco crítico.

## Avaliação

Quando esta aula estiver pronta, o link direto da avaliação aparecerá aqui, e você poderá escrever:
